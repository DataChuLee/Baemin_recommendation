# 배민 리뷰 기반 메뉴/맛집 추천

## 비용 절감 방법

### 문제 해결 방법 검토
- 꼭 생성형 AI로 풀어야 할 문제인가?
- 더 저렴한 비용으로 풀 수 있는 방법은 없을까? 
    - Machine Learning, Heuristic 또는 Rule-Based
- 상대적으로 고비용인 생성형 AI로 문제를 해결했을 때 어떠한 가치를 창출 할 수 있을까?

### 실시간 VS 비실시간
- 실시간은 기본적으로 호출량이 사용자 사용 빈도에 의해 결정됨
- 비실시간 또는 배치 기반 LLM 서비스는 배치의 주기의 따라 결정되어 비용은 효과적으로 컨트롤 할 수 있음
- LLM API 또한 Batch API 호출 시 할인폭이 큰 편
- 대화형 시나리오에서는 어려우나 그 외 시나리오에서는 고려 가능함

### Model Selection
- OpenAI, Anthropic, Google의 API 간에도 가장 비싼 모델과가장 저렴한모델의가격 차이는약70배
- 5천만명이 한꺼번에 간단한 요약 결과 요청 시 Claude 3 Opus 가격 약 17억, Gemini Flash는 약 2천만원
- 더 저렴한 모델은 좀 더 정교하고 긴 Prompt가 필요할 수 있으나 그걸 감안해도 유의미한 가격 차이 발생
- 모델 라인업이 보통 성능 측면에서 상-중-하로 나뉘는 편 인데 같은 등급끼리는 성능 비교 권장

### Rate Limit
- 보통 무료 서비스에서 취하는 전략이며, N회 이상 호출 후 일정 시간 동안 사용 제한

### Prompt Caching
- Prompt caching은 앞의 Prompt 일부 또는 전체를 Caching 하는 기능
- 첫 Cache 적용은 기존 대비 25% 더 비싸지만 Caching한 Prompt 호출 할 때의 가격은 기존 대비 1/10 수준

### Vector DB
- 동일한 쿼리에 대해 여러번 Embedding API 호출이 필요한 경우 유용한 편
- 코드 중 메뉴에 대한 벡터 DB는 구축했는데, 추가로 쿼리에 대해서도 구축하여 추가적인 비용 절감이 가능

### Heuristic Classifier
- LLM 호출이 필요한 지 필요하지 않는 지를 판단 LLM API 호출 이전 단계에서 파악
- 예를 들어, 대화형 시나리오에서 비속어 탐지 시 준비된 답변 사용

### Prompt Engineering
- Prompt 간단 명료하게 작성하기 (Input Tokens 최적화)
- Few-Shot이 많다고 성능이 지속적으로 증가하지 않을 수 있음
- Output Tokens이 동일한 Output Tokens 대비 더 비싼 편인데, 상대적으로 더 짧게 대답을 끝내도록 유도 할 수 있음
- 불필요한 공백 문자,줄 바꿈 제거
